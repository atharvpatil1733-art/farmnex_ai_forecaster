## Important findings

- **Truncated exports:** 9 of 14 files have exactly [1000] data rows, a typical download cap. Each keeps only the newest rows, so older dates are missing (see the per-file date ranges below). Re-export in smaller windows (e.g. one quarter per file) to recover the full history.
- `2026_onion_price_data.csv`: file name says 2026 but every date is in [2025].
- `2026_onion_quantity_data.csv`: file name says 2026 but every date is in [2025].
- `2026_potato_price_data.csv`: file name says 2026 but every date is in [2025].
- `2026_potato_quantity_data.csv`: file name says 2026 but every date is in [2025].
- `2026_tomato_price_data.csv`: file name says 2026 but every date is in [2025].
- Collapsed varieties: 5015 variety rows -> 5015 market-days (0 market-days had more than one variety; modal = plain mean because price exports have no per-variety arrivals).
- **Onion**: no real data at all for calendar month(s) Jan, Feb, Mar, Apr, Nov, Dec; seasonal (monthly) models will lean on synthetic data or fallbacks for those months.
- **Tomato**: no real data at all for calendar month(s) Jan, Feb, Mar, Nov, Dec; seasonal (monthly) models will lean on synthetic data or fallbacks for those months.
- **Potato**: no real data at all for calendar month(s) Jan, Feb, Nov, Dec; seasonal (monthly) models will lean on synthetic data or fallbacks for those months.
- **Tomato** has no quantity data: arrivals_tonnes is left empty (NaN) on all rows (0 non-empty). Arrivals were not estimated or invented.
- Missing days (Sundays, holidays, non-reporting) are left missing; nothing is interpolated or forward-filled.
