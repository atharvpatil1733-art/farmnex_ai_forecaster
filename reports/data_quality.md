## Important findings

- **Truncated exports:** 9 of 14 files have exactly [1000] data rows, a typical download cap. Each keeps only the newest rows, so older dates are missing (see the per-file date ranges below). Fix: `python -m forecaster.ceda` (API, full history).
- `2026_onion_price_data.csv`: file name says 2026 but every date is in [2025].
- `2026_onion_quantity_data.csv`: file name says 2026 but every date is in [2025].
- `2026_potato_price_data.csv`: file name says 2026 but every date is in [2025].
- `2026_potato_quantity_data.csv`: file name says 2026 but every date is in [2025].
- `2026_tomato_price_data.csv`: file name says 2026 but every date is in [2025].
- Collapsed varieties: 5015 variety rows -> 5015 market-days (0 market-days had more than one variety; modal = plain mean because price exports have no per-variety arrivals).
- **Onion**: no real prices for calendar month(s) Jan, Feb, Mar, Apr, Nov, Dec; seasonal (monthly) models will lean on synthetic data or fallbacks there.
- **Tomato**: no real prices for calendar month(s) Jan, Feb, Mar, Nov, Dec; seasonal (monthly) models will lean on synthetic data or fallbacks there.
- **Potato**: no real prices for calendar month(s) Jan, Feb, Nov, Dec; seasonal (monthly) models will lean on synthetic data or fallbacks there.
- **Tomato**: no quantity data found, arrivals_tonnes is empty (NaN) on all rows. Arrivals were not estimated or invented; the arrivals model and the demand signal fall back to synthetic data for this crop.
- Missing days (Sundays, holidays, non-reporting) are left missing; nothing is interpolated or forward-filled.
